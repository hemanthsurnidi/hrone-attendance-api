# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72–74) | Unconditionally returned `{"status": "ok"}` with 200 without checking if MongoDB was reachable. | If MongoDB is shut down or unreachable, the endpoint still returns 200 OK instead of 503 Service Unavailable. | Added `client.admin.command('ping')` inside a `try/except` block, raising `HTTPException(503)` on connection failure. |
| 2 | Startup / Lifespan (missing) | No database indexes were created at application startup. | Concurrent creates caused duplicate documents; `explain` queries showed slow collection scans (`COLLSCAN`) on large datasets. | Implemented an asynchronous FastAPI `lifespan` handler that idempotently creates unique and compound indexes on startup. |
| 3 | `compute_late_minutes` (lines 33–37) | Late calculation boundary bug due to integer division before comparison (`minutes > 10`), plus missing IST conversion and instant truncation (R1, R2). | For shift 09:30, punch-in at 09:40:01 has elapsed seconds = 601. `int(601/60) = 10`, so `10 > 10` evaluates to False, returning 0 instead of 10. | Converted punch-in to IST, truncated to whole seconds, compared elapsed seconds against 600 (`diff_sec > 600`), and floor-divided total seconds by 60 (`diff_sec // 60`). |
| 4 | `compute_work_hours` (lines 40–41) | Used Python's built-in `round()` which performs Banker's Rounding (round-half-to-even) instead of round-half-up (R4). Also lacked whole-second truncation (R1). | A duration of 2.675 hours rounded to 2.67 instead of 2.68. | Truncated inputs to whole seconds, converted to `Decimal`, and applied `ROUND_HALF_UP` to 2 decimal places. |
| 5 | `compute_overtime` (lines 44–47) | Violated Rule R3 by awarding overtime for any positive minutes (< 30 min), and computed overtime against the same calendar day for overnight shifts. | 15 minutes of overtime was returned as 15 instead of 0. For overnight shifts (e.g. 22:00 to 06:00), punch-out at 06:10 next morning computed > 24 hours of overtime. | Added the $\ge 30$ minutes threshold (otherwise 0), and advanced the shift end target date by +1 day whenever `shift_end <= shift_start`. |
| 6 | `create_employee` (lines 79–83) | Check-then-insert race condition (`find_one` then `insert_one`), and missing input validation. | Two concurrent POST requests with the same `emp_code` created duplicate employees. Sending `emp_code="invalid"` or identical `shift_start` and `shift_end` was accepted. | Added unique index on `emp_code` and caught `DuplicateKeyError` to return 409. Validated regex patterns and verified `shift_start != shift_end` via Pydantic model validator (returning 422). |
| 7 | `create_employee` (line 82) | Stored naive local datetime in MongoDB and returned raw Python datetime object in API response instead of integer epoch milliseconds. | Client received ISO string or serialization error instead of integer timestamp >= 100000000000. | Stored UTC datetime with second truncation in MongoDB and formatted `created_at` as epoch milliseconds in API response. |
| 8 | `list_employees` (line 93) | Pagination offset calculation error: `skip = page * page_size`. | For `page=1`, skipped the first 20 records (`skip=20`), so page 1 was never visible. | Changed pagination formula to `skip = (page - 1) * page_size`. |
| 9 | `list_employees` (line 94) | Counted all documents in the collection (`count_documents({})`), ignoring the department query filter (violating Rule R10). | Filtering by a department with 2 employees returned `total = 100` instead of `total = 2`. | Passed the query filter `q` into `count_documents(q)`. |
| 10 | `list_employees` (line 95) | Missing sorting by `emp_code` ascending. | Employees returned in arbitrary BSON storage order. | Added `.sort("emp_code", ASCENDING)` to the MongoDB query cursor. |
| 11 | `punch_in` (line 101) | Did not check if employee existed before accessing `emp["shift_start"]`. | Punching in with an unregistered employee code threw an unhandled `TypeError` (HTTP 500) instead of HTTP 404. | Checked `emp is None` and raised `HTTPException(404, detail="Employee not found")`. |
| 12 | `punch_in` (lines 102–103) | Derived attendance date using server local date `datetime.now().date()` instead of IST calendar date, and lacked overnight shift support (R1). | Punch-in at 00:30 IST for an overnight shift (22:00 to 06:00) was filed on the wrong day instead of the previous day's shift date. | Implemented `get_attendance_date` to convert to IST and shift date back 1 day when punch-in occurs before `shift_end` of an overnight shift. |
| 13 | `punch_in` (lines 104–105) | Check-then-insert race condition on punch-in. | Two simultaneous punch-in requests for the same date both passed `find_one` and created duplicate attendance documents. | Created unique compound index on `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409. |
| 14 | `punch_in` (line 119) | Added `"id": str(res.inserted_id)` to the response document. | Response payload contained internal database `id`, violating the OpenAPI contract. | Removed `id`/`_id` and formatted response strictly according to `AttendanceRecord`. |
| 15 | `list_attendance` (lines 144–146) | Fetched entire collection into Python memory (`list(find())`) and sorted in Python. | On ~100k records, caused severe memory spike / out-of-memory crash. Also failed to sort ties by `emp_code` ascending. | Handled sorting and pagination on the MongoDB cursor directly using compound index `[("date", -1), ("emp_code", 1)]`. |
| 16 | `list_attendance` (lines 136–141) | Missing date range validation for `date_from > date_to`. | Querying `date_from=2026-07-10&date_to=2026-07-01` returned 200 with empty list instead of HTTP 422. | Added validation raising `HTTPException(422)` when `date_from > date_to`. |

### Items examined and decided were NOT defects:
1. **PyMongo Synchronous Driver**: FastAPI runs synchronous endpoint definitions in a dedicated threadpool (`starlette.concurrency.run_in_threadpool`), preventing blocking of the main event loop while maintaining simpler synchronous database driver mechanics.
2. **Calendar Dates and Shift Times as Plain Strings**: Storing `date`, `joined_on`, `shift_start`, and `shift_end` as `YYYY-MM-DD` and `HH:MM` strings in MongoDB rather than BSON dates is deliberate per `DATA_MODEL.md` to prevent timezone offsets from altering calendar dates.
